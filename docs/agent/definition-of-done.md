# Definition of done

A task is complete only when all applicable items are satisfied.

## Product

- Acceptance criteria are met
- The behavior stays within approved game-design rules
- Out-of-scope behavior was not added
- A human-readable reproduction path exists

## Engineering

- Code follows existing module boundaries
- Persistent and competitive outcomes remain server authoritative
- Failure cases are handled
- Logging is meaningful and excludes secrets
- New dependencies are justified

## Verification

- Relevant unit tests pass
- Relevant integration tests pass
- Client type checking and lint pass
- Server build and analyzers pass
- Deterministic systems have repeatability tests
- Manual or automated demonstration evidence is recorded

## Delivery

- Documentation is updated
- Decisions are recorded
- Known limitations are explicit
- The branch contains only task-related changes
- The nightly report is complete

If validation cannot run, the task must be reported as incomplete with the exact blocker.
